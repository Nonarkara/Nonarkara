# Contributing

This repository is the GitHub **profile front door** for [Dr Non / Non Arkaraprasertkul](https://github.com/Nonarkara) — a Bangkok civic studio under Axiom X Co., Ltd. It is meant to be read, not to hold product source.

Learners are welcome. Secrets are not.

## What to open where

| You want to… | Open it on |
|---|---|
| Fix a typo, dead link, or unclear path on this profile | an issue or pull request **here** (`Nonarkara/Nonarkara`) |
| Ask how a **blueprint** works (data, formula, architecture) | the blueprint repo — start with [FloodDash-Blueprint](https://github.com/Nonarkara/FloodDash-Blueprint) |
| Propose a fork, rebuild, or city-specific adaptation | the repo you forked; link your work in the issue |
| Report a broken **live** dashboard | the repo named in that project's README, with the URL and what you expected to see |
| Request private source, production keys, unpublished scores, or internal runbooks | **nowhere** — those are out of scope |

Thai and English are both first-class. Write in whichever you think in.

## Fork the method, not the secrets

Several public repos are **invitations to rebuild** (blueprints, playbooks, design cores). They publish architecture, formulas, public-data catalogs, and design language **on purpose**. They do not publish the private system that may already be running.

Please:

- Fork and adapt **method**: pipelines, scoring formulas, information architecture, bilingual UX patterns.
- Keep **measured** numbers labelled as readings (sensor, satellite, station, document).
- Keep **modelled** numbers labelled as models, with the formula you used.
- Attribute the studio when you reuse substantial text, diagrams, or formulas (see each repo's licence).
- Do **not** present a fork as an official depa, ASEAN, municipal, or Axiom X product unless that institution has actually commissioned or published it.
- Do **not** scrape, leak, or guess at withheld implementations, credentials, or operator-only modules.

If a README says “no source code” or “independent; not an official site,” take that as a hard line, not a prompt.

## Issues that help

Useful issues are specific:

- the URL you opened
- what the page or README claimed
- what you actually saw (or which link 404'd)
- whether you are a visitor, a builder, or a city practitioner

Not useful: requests for star counts, endorsements, or “send me the dashboard source.”

## Pull requests on this repo

This repo should stay a **short learner-facing profile**: hero, identity, three paths, two maps, featured links, principles, connect. Do not turn it into a badge wall, a changelog, or a second copy of every project README.

Before you add a link, confirm the repository or site still exists and that the one-line description matches the repo's own README — do not invent awards, official status, or telemetry.

## Safety and civic use

Dashboards and indexes here are **attention tools**, not warning issuers and not substitutes for agencies (for example DDPM / TMD / ONWR on flood, or the authorities that publish official air-quality notices). If your fork could be mistaken for an official alert channel, say that it is not — in the README, on the page, and in the UI.
